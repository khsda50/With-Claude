## B. 자기소개서 1 — 지원동기 / 향후 계획 / 퇴사 동기 (915자)

| 구성 | 역할 |
|---|---|
| 지원동기 | **직무 전환 논리** — 3회 탈락에서 비어 있던 부분 |
| 향후 계획 | Mixed-Signal을 갭이 아니라 계획으로 |
| 퇴사 동기 | 전 직장 비판 없이 구조적 이유로 |

```text
[지원동기]
검증 환경을 만드는 일에 가장 오래 붙어 있었습니다. Ethernet GMAC은 UVM 검증 환경을
직접 구현해 사내 재사용 표준의 기준이 되게 했고, UVM 이전 세대의 SystemVerilog class
기반 고객사 AMBA VIP는 인수해 구조를 파악하고 확장했습니다. 전사 IP Unit 시뮬레이션
환경과 Coverage DB 병합 플로우도 세웠습니다. 다만 이 일들은 과제 일정이 허락하는
만큼이었고, 검증 환경을 만드는 것이 상시 업무인 자리는 아니었습니다.

HBM Digital Design(검증) 조직은 담당 업무 네 가지 중 두 가지가 In-house VIP 개발과
UVM 검증 환경 구성입니다. HBM base die에는 표준 VIP가 없는 In-house IP와
Analog-Digital Mixed IP가 많아, 스펙을 읽고 검증 환경을 직접 설계하는 일이 상시로
필요한 조직이라고 이해했습니다. 제가 가장 오래 해온 일이 이 조직에서는 곁일이 아니라
본업이라는 점이 지원 이유입니다.

[향후 계획]
담당 IP의 검증 환경을 스펙 단계부터 맡아 커버리지로 닫는 사이클을 반복하며, 재사용
가능한 In-house VIP 자산을 남기는 엔지니어가 되고자 합니다. 3년 내에는 Mixed-Signal
검증까지 범위를 넓혀, 디지털 검증만으로 판단이 어려운 구간에서 회로 설계자와 같은
언어로 논의할 수 있는 검증 담당자가 되는 것이 목표입니다.

[전 직장 퇴사 동기]
현 직장에서 양산 tape-out까지 경험했지만, 디자인하우스는 과제 단위로 움직여 tape-out
이후 다음 과제로 이동합니다. 같은 IP를 세대에 걸쳐 깊게 파고 실리콘 결과가 다음 설계로
돌아오는 과정을 끝까지 보는 경험은 구조적으로 얻기 어려웠습니다. 제품을 오래 책임지는
자리에서 검증 역량을 쌓고 싶어 이직을 결심했습니다.
```

- 공백 포함 **915자** / 1,000자 → 여유 85자
- **전환 논리를 바꿨습니다.** 이전 초안은 *"상용 VIP 도입 비중이 컸다 → 그래서 만드는
  자리로 가고 싶다"* 였는데, 경력기술서가 *"이미 여러 번 만들었다"* 로 서 있어 톤이
  어긋났습니다. 이제는 **"해왔지만 그 일이 상시 업무가 아니었다 → 상시인 조직으로"** 입니다.
  같은 사실인데 "못 해봤다"가 아니라 "더 할 자리가 필요하다"로 읽힙니다.
- 고객사 AMBA VIP 항목이 이 논리를 받칩니다. VIP를 블랙박스로 쓴 사람이 아니라
  **내부를 다뤄온 사람**이라는 근거가 되기 때문입니다.
- 마지막 문장이 이 문항의 핵심입니다 — *"제가 가장 오래 해온 일이 이 조직에서는 곁일이
  아니라 본업"*.
- 퇴사 동기와 지원동기를 **같은 논리축**으로 묶었습니다(과제 단위 이동 → 한 IP를 오래
  못 봄). 이전 초안은 둘이 다른 불만을 말하고 있었습니다.

- **미실행 상태는 여기서 언급하지 않았습니다.** 서류에 쓸 필요가 없고, 면접에서 물으면

## H. 내일 CRMU 적용 결과에 따라 바뀌는 것

`q_chan_vip` 을 사내 CRMU requester / CPU responder 인터페이스에 bind 해서 돌아가면,
지원서의 무게중심이 이동합니다.

**성공 시 바뀔 것**

- C ①블록의 Q-Channel 문장이 `개인 과제로` → **사내 과제**로 승격. 이 프레임에서 가장
  강한 사례가 됩니다: *설계가 완성되기 전에 검증 환경을 먼저 세워 투입했다.*
- 담당업무 칸(A)에 Q-Channel 항목이 들어갈 수 있게 됩니다 (지금은 개인 과제라 제외).
- D의 "지금 만들고 있는 것" 서술이 실행 결과를 포함하는 형태로 바뀝니다.
- E(경험/특허) 칸이 불필요해질 수 있습니다.

**순서 주의**

되고 나서 씁니다. 미리 써두고 안 붙으면 되돌려야 합니다. 신호 네이밍, 클럭 도메인,
리셋 시 QREQn 초기값(`cfg.reset_qreqn_high`), active-low 규약에서 시간이 걸릴 수 있습니다.

**첫 컴파일에서 걸릴 만한 곳** (이 코드는 한 번도 컴파일된 적이 없습니다)

- `covergroup ... with function sample(...)` — 막히면 아이템을 클래스 멤버에 저장하고
  인자 없는 `sample()` 로 바꾸는 우회
- `coverpoint ... iff (...)` — guard 가 sample 인자를 참조. 막히면 guard 를 `write()` 의
  `if` 로 옮기고 covergroup 을 쪼개기
- `bins long = {[32:$]}` — `int unsigned` 에 `$` 사용, 경고 가능
- `get_inst_coverage()` — 커버리지 수집 옵션 없이 컴파일하면 0. 테스트는 이미 에러
  조건으로 쓰지 않음
- 컴파일 순서: `qch_if.sv` → `qch_items.sv` → `qch_agent_pkg.sv` → 테스트

**공개 저장소 오염 주의**

`khsda50/With-Claude` 는 **public** 입니다. 실제 신호 이름·인터페이스 구조·config 값·
파형·커버리지 결과가 push 되면 되돌려도 git 이력에 남습니다. 회사 PC 에서 이 저장소를
clone 하지 말고 **파일만 복사**해 가시면 실수로 push 할 경로 자체가 없습니다.
